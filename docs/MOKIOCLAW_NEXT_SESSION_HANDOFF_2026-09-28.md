## 1. 项目目标与已确定的产品方向

MokioClaw 的长期目标是面向真实代码仓库的 **Issue → Patch → Test → Review** 维护 Agent。最终演示希望以 GitHub 账户为入口，直观列出该账户可访问的**私有仓库**，进入仓库后浏览提交历史及对应的审查信息。为了尽快形成可用产品入口，用户先选择了**本地 Git 仓库 + 本地浏览器页面**，并把第一版“风险”明确限定为**改动审查优先级**。

当前页面的 `high`、`medium`、`low` 是人工审查顺序建议；`manual_review` 表示合并、二进制或统计缺失等无法可靠机械判断的情况。它们均不代表发现漏洞、预测事故概率或 Agent 修复成绩。该语义以及 `review-priority-v1` 的规则版本，后续接入 GitHub 时应继续保持；如果改变规则输入或阈值，必须另行设计并升级版本。

**2026-09-28 新增方向：**用户希望把项目早期已有的 CodeAgent 能力接入这一本地工作台迭代。建议先让用户从明确选择的本地仓库和固定提交手动创建维护任务，在页面查看运行状态、补丁与验证证据；待本地闭环可靠后，再接入私有 GitHub 仓库来源。此处只是后续设计目标，不表示当前页面已有 Agent 运行能力。

## 3. 后续阶段性目标清单（建议，尚未授权实施）

### 路线判断：先复用本地 CodeAgent，再连接 GitHub

| 路线 | 优点 | 主要代价 | 建议 |
| --- | --- | --- | --- |
| 从网页直接调用现有 CLI/Agent，并使用来源仓库作为 workspace | 接口看似最短 | 主机命令可越出 workspace；来源树、审批、运行日志和并发都缺乏网页级边界 | 不采用 |
| 本地仓库固定 SHA → 隔离任务副本 → 复用现有 Agent 事件流 → 人工审阅结果 | 最快把早期 CodeAgent 与新产品入口串成真实闭环，暂不依赖 GitHub 授权 | 需要任务协调、执行隔离、浏览器审批和脱敏展示 | **优先设计和实施** |
| 先完成 GitHub 账户接入，再连接 Agent | 更贴近最终演示入口 | 认证、私有数据与远端写权限会叠加 Agent 执行问题 | 放在本地 Agent 闭环之后 |

推荐路线只指**实施顺序**。是否允许运行模型、测试或真实 Agent 任务，仍须用户为具体下一阶段明确授权；本交接文档不授予运行权限。
